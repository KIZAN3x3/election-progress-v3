## 9. 未ログインで読めないことの確認

publishable key は `config.js` の値を環境変数に入れて使う（コマンドに直接書かない）。

```bash
export SB_URL="https://hhlqgxmhbpfhjnjmradq.supabase.co"
export SB_PUBLISHABLE="<config.js の SUPABASE_KEY>"

# 読み取り → 見込み: []（0件）
curl -s "$SB_URL/rest/v1/v3_candidates?select=id&limit=1" -H "apikey: $SB_PUBLISHABLE"; echo
curl -s "$SB_URL/rest/v1/v3_progress?select=id&limit=1"   -H "apikey: $SB_PUBLISHABLE"; echo

# 書き込み（存在しない id を指定するので、万一通っても何も変わらない）→ 見込み: 401 / 403（permission denied）
curl -s -o /dev/null -w "%{http_code}\n" -X PATCH \
  "$SB_URL/rest/v1/v3_candidates?id=eq.00000000-0000-0000-0000-000000000000" \
  -H "apikey: $SB_PUBLISHABLE" -H "Content-Type: application/json" -d '{"name":"x"}'

# Edge Function の候補者登録を publishable key だけで呼ぶ（空の配列なので、万一通っても何も作られない）→ 見込み: 401
curl -s -w "\n%{http_code}\n" -X POST "$SB_URL/functions/v1/v3-sync-progress" \
  -H "apikey: $SB_PUBLISHABLE" -H "Authorization: Bearer $SB_PUBLISHABLE" -H "Content-Type: application/json" \
  -d '{"action":"createCandidate","candidates":[]}'

# 利用者一覧を publishable key だけで呼ぶ → 見込み: 401
curl -s -w "\n%{http_code}\n" -X POST "$SB_URL/functions/v1/v3-users" \
  -H "apikey: $SB_PUBLISHABLE" -H "Authorization: Bearer $SB_PUBLISHABLE" -H "Content-Type: application/json" \
  -d '{"action":"list"}'
```

- [ ] 画面：管理者で一覧・詳細が出る。承認待ちのアカウントでは「承認待ちです」が出る
- [ ] GitHub Actions の同期を手動実行し、成功すること（「対象候補者: N件」が 2. の件数のうちシートのある分と合うこと）

**戻し方**: 8. を戻す。
